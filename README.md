Two lines explaining one everyday thing — a toaster — to a 10-year-old. Line 1 is a single vivid sentence built on one concrete, surprising analogy; line 2 says in one sentence why that analogy works, naming what it maps and what it leaves out. A judge model compares entries two at a time and the best wins.

## The entry

> A toaster is a tiny tanning bed where bread lies down to get brown on both sides, then pops up when it is done.
>
> It works because both brown something lying flat with heat on a timer, but it leaves out that bread never chooses to lie down and a real sun never pops anything up when it is done.

Two lines, 292 characters. The analogy joins the kitchen appliance to the beach ritual: bread lies down flat, heat browns it on both sides, a timer decides when it is done — and then the pop-up, which no sun ever does. Line 2 is honest about the limits: the bread has no choice in the matter, and a real sun never pops anything up.

## Run it

```sh
node main.ts
```

`main.ts` writes the entry to `/output/entry.txt` (292 bytes, no trailing newline) and refuses loudly if the text ever leaves the two-line, 1–400-character gate.
